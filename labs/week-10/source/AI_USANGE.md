## ครั้งที่ 1

**ถามอะไร**
- สอบถามเกี่ยวกับการเชื่อมต่อ Node.js กับ SQLite ด้วยโมดูลในตัว `node:sqlite` (`DatabaseSync`) ว่ามีรูปแบบการทำงานเป็น Synchronous หรือ Asynchronous และทำไมต้องรันคำสั่ง `PRAGMA foreign_keys = ON;` ทุกครั้งที่เปิดการเชื่อมต่อ

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- `DatabaseSync` ใน `node:sqlite` ทำงานแบบ Synchronous เนื่องจาก SQLite อ่านเขียนไฟล์ฐานข้อมูลใน Local Disk โดยตรง ไม่ต้องรอ Network I/O เหมือนฐานข้อมูลประเภท Client-Server และ SQLite ปิดการบังคับใช้ Foreign Key เป็นค่าเริ่มต้นเพื่อความเข้ากันได้ย้อนหลัง จึงต้องสั่งเปิดด้วย `PRAGMA foreign_keys = ON;` เสมอ เพื่อให้การตรวจสอบความสัมพันธ์ระหว่างตารางทำงานได้จริง

**ใช้ส่วนไหน / แก้เองตรงไหน**
- นำความเข้าใจไปเขียนฟังก์ชัน `loadSeed()` และเปิดการเชื่อมต่อฐานข้อมูลใน `requestService.js` พร้อมตั้งค่า `PRAGMA foreign_keys = ON`

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 2

**ถามอะไร**
- สอบถามแนวคิดการทำ Data Mapping ระหว่าง Database Schema กับ API Contract ว่าเหตุใดในฐานข้อมูลจึงควรเก็บ `requester_id` เป็นตัวเลข แต่ API ต้องคืนค่า `requesterName` เป็นข้อความ และควรออกแบบฟังก์ชันสำหรับแปลงชื่อผู้ใช้เป็นรหัส id อย่างไร

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- ฐานข้อมูลจัดเก็บแบบ Normalization โดยใช้ `requester_id` ชี้ไปยังตาราง `users` เพื่อป้องกันข้อมูลชื่อและอีเมลซ้ำซ้อน แต่ฝั่ง Frontend ต้องการชื่อผู้แจ้งเพื่อนำไปแสดงผลบนหน้าจอทันที ชั้น Service จึงต้องทำหน้าที่เป็นตัวแปลงด้วยการ `JOIN users` และตั้งชื่อ Alias ด้วย `AS requesterName` ส่วนการสร้างคำร้อง ฟังก์ชัน `resolveUserId()` จะค้นหาชื่อในฐานข้อมูล หากยังไม่มีจะสร้างผู้ใช้ใหม่ให้อัตโนมัติ

**ใช้ส่วนไหน / แก้เองตรงไหน**
- นำหลักการไปเขียนฟังก์ชัน `findAll()`, `findById()` และ `resolveUserId()` ใน `requestService.js` เพื่อให้เชื่อมโยงข้อมูลระหว่างตาราง `requests` และ `users` ได้อย่างถูกต้อง

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 3

**ถามอะไร**
- สอบถามเกี่ยวกับกลไกการป้องกัน SQL Injection ด้วย Parameterized Query (`?`) และเหตุผลว่าทำไมเครื่องหมาย `?` ถึงไม่สามารถใช้แทนชื่อคอลัมน์ในคำสั่ง `ORDER BY` ได้ พร้อมทั้งหลักการทำงานของ Allowlist

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- เครื่องหมาย `?` (Placeholder) มีหน้าที่รับเฉพาะ "ค่าของข้อมูล" (Data Literal) เท่านั้น จึงช่วยป้องกันไม่ให้ค่าจากภายนอกถูกตีความเป็นคำสั่ง SQL แต่ไม่สามารถใช้แทน Identifier เช่น ชื่อตารางหรือชื่อคอลัมน์ได้ เพราะขัดกับไวยากรณ์ SQL หากต้องการให้ผู้ใช้เลือกคอลัมน์เรียงลำดับได้ จะต้องตรวจสอบค่าด้วย Allowlist ก่อน เพื่อคัดกรองเฉพาะคอลัมน์ที่อนุญาตอย่างปลอดภัย

**ใช้ส่วนไหน / แก้เองตรงไหน**
- ตรวจสอบทุกคำสั่ง SQL ใน `requestService.js` ให้ใช้ Parameterized Query ทั้งหมด และนำแนวคิดการโจมตีไปทดสอบยิง SQL Injection 3 รูปแบบ เพื่อบันทึกผลลงใน `API_CONTRACT.md` และ `SECURITY_TEST.md`

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 4

**ถามอะไร**
- สอบถามเกี่ยวกับการแปลง Error ของฐานข้อมูล SQLite (เช่น `CHECK constraint failed`, `FOREIGN KEY constraint failed`) ให้กลายเป็น HTTP Status Code ที่เหมาะสม (400/409) ด้วย `AppError` แทนที่จะปล่อยให้ตอบ 500

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- Error ที่เกิดจากการละเมิด Constraint ส่วนใหญ่เป็นความผิดพลาดจากฝั่งผู้ใช้ที่ส่งข้อมูลไม่ตรงตามข้อกำหนด จึงไม่ควรตอบ 500 ซึ่งสื่อถึงข้อผิดพลาดภายในเซิร์ฟเวอร์ ควรดักจับ Error ในชั้น Service แล้วแปลงด้วยฟังก์ชัน `toAppError()` ให้เป็น `AppError` ที่มี status `400` หรือ `409` พร้อมข้อความภาษาไทยที่เข้าใจง่าย และไม่เปิดเผยโครงสร้างตารางภายในให้ผู้ใช้ภายนอกเห็น

**ใช้ส่วนไหน / แก้เองตรงไหน**
- นำไปเขียนฟังก์ชัน `toAppError()` และครอบบล็อก `try...catch` ในฟังก์ชัน `create()` ของ `requestService.js`

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 5

**ถามอะไร**
- สอบถามหน้าที่การทำงานของ `asyncHandler` ใน Express รวมถึงแนวคิดการใช้ Database Transaction (`BEGIN`, `COMMIT`, `ROLLBACK`) ในขั้นตอนการสร้างคำร้อง

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- `asyncHandler` ทำหน้าที่เป็นตัวครอบฟังก์ชันแบบ async เพื่อดักจับ Promise Rejection แล้วส่งต่อให้ `next(err)` อัตโนมัติ ป้องกันไม่ให้คำขอค้างใน Express 4 ส่วน Transaction มีไว้เพื่อรักษาคุณสมบัติ Atomicity ในกรณีที่ `resolveUserId()` สร้างผู้ใช้ใหม่สำเร็จ แต่คำสั่ง `INSERT INTO requests` ล้มเหลว ตัว `ROLLBACK` จะยกเลิกการสร้างผู้ใช้เพื่อไม่ให้เกิดข้อมูลขยะตกค้างในฐานข้อมูล

**ใช้ส่วนไหน / แก้เองตรงไหน**
- นำ Transaction (`db.exec('BEGIN')`, `COMMIT`, `ROLLBACK`) ไปใส่ในฟังก์ชัน `create()` ของ `requestService.js` เพื่อความสมบูรณ์ในการทำงาน

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ
