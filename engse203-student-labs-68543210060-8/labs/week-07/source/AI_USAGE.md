# AI_USAGE — LAB 07

บันทึกการใช้ AI ระหว่างทำงาน · **ใช้ AI ได้ แต่ต้องเป็นเจ้าของโค้ดที่ส่ง**

> ผู้สอนจะสุ่มถามจากโค้ดที่ส่ง — ถ้าอธิบายไม่ได้ คะแนนส่วนนั้นจะถูกทบทวน

---

## ครั้งที่ 1

**ถามอะไร**
ถามสาเหตุที่ Test case ข้อ 3 (`GET /api/requests/:id ไม่ถูก`) ทดสอบไม่ผ่าน (คาดหวัง 404 แต่ได้ 500) โดยให้ AI อธิบายโดยไม่ต้องรันโค้ด

**AI ตอบว่าอย่างไร (สรุปสั้น)**
AI อธิบายว่าใน `requestController.js` มีการสั่ง `throw new AppError(...)` แต่ไม่ได้ import `AppError` เข้ามา ทำให้เกิด `ReferenceError` เมื่อ Express ส่ง Error นี้ไปยัง Error Handler ก็จะถูกมองว่าเป็น Internal Server Error (500) และยังพบว่าใน `errorHandler.js` ก็ลืม import `config` เข้ามาเช่นกัน

**ใช้ส่วนไหน / แก้เองตรงไหน**
ทำการแก้โดยเพิ่ม `import { AppError } from '../middleware/errorHandler.js';` ในไฟล์ Controller และเพิ่ม `import { config } from '../config.js';` ในไฟล์ Error Handler

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 2

**ถามอะไร**
สอบถามวิธีแก้ไข Error `ERR_MODULE_NOT_FOUND` ที่เกิดขึ้นหลังจากทำการ import โมดูลตามที่ AI แนะนำไปก่อนหน้า

**AI ตอบว่าอย่างไร (สรุปสั้น)**
AI อธิบายว่าโปรเจกต์นี้ใช้ระบบ Module แบบ ES Modules (ESM) ซึ่งมีกฎบังคับว่าการ import ไฟล์ในโปรเจกต์เดียวกันจะต้องระบุนามสกุลไฟล์ `.js` เสมอ

**ใช้ส่วนไหน / แก้เองตรงไหน**
เข้าไปแก้บรรทัด import ที่เพิ่งเติมเข้าไปใหม่ ให้มีนามสกุล `.js` ต่อท้าย เช่น `import { config } from '../config.js';`

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 3

**ถามอะไร**
ถามว่าควรนำ `AppError` ไปปรับใช้กับทุก Error ใน Controller เลยหรือไม่ และฟีเจอร์ที่ไม่ให้ส่ง stack trace ออกไปตอน Production มีการทำไว้แล้วหรือยัง

**AI ตอบว่าอย่างไร (สรุปสั้น)**
AI แนะนำว่าเป็น Best Practice ที่ควรใช้ `AppError` กับทุกจุด เพราะทำให้โค้ดสะอาด ตอบกลับเป็นมาตรฐานเดียวกัน และช่วยแยกหน้าที่การจัดการ Error ออกจาก Controller ได้ชัดเจน ส่วนเรื่อง stack trace นั้น AI ยืนยันว่าใน `errorHandler.js` มีการเขียนเช็ก `config.isProduction` ไว้เรียบร้อยแล้ว

**ใช้ส่วนไหน / แก้เองตรงไหน**
นำแนวคิดนี้ไปพิจารณาปรับแก้โค้ด Error เดิมที่เป็น `res.status(...).json(...)` ให้มาใช้การโยน `AppError` แทนเพื่อความเป็นระเบียบ

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ
